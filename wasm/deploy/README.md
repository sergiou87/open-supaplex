# OpenSupaplex — self-contained browser deployment

Everything the game needs is in this folder; nothing is fetched from outside it
(no CDN, no analytics, no external assets). Host it anywhere static files can
be served, or embed it in another site as described below.

## Files

| File                  | Purpose                                              |
|-----------------------|------------------------------------------------------|
| `index.html`          | Minimal loader shell (canvas + `Module` config)      |
| `opensupaplex.js`     | Emscripten runtime glue, generated by the build      |
| `opensupaplex.wasm`   | Game engine                                          |
| `opensupaplex.data`   | Game assets (~9 MB, packed by `--preload-file`)      |

The three `opensupaplex.*` files must stay together in the same directory; the
runtime resolves them relative to the location of `opensupaplex.js`, not the
embedding page.

## Serving it

Any static file server works, e.g.:

```sh
python3 -m http.server 8000
```

Opening `index.html` directly from disk (`file://`) does **not** work: browsers
block fetching the `.wasm`/`.data` files without an HTTP origin.

Serve `.wasm` with `Content-Type: application/wasm` if your server doesn't
already (all common ones do), and enable gzip/brotli if you can — the `.js` and
`.data` compress very well.

## Browser support

The build uses JSPI (JavaScript Promise Integration) for its main loop:

- Chrome / Edge 137+ (May 2025)
- Firefox 139+
- Safari 27+

## Embedding in a third-party site

### Option A — iframe (simplest)

```html
<iframe src="https://your-host.example/opensupaplex/" width="1280" height="800"
        style="border:0" allow="fullscreen"></iframe>
```

No CORS configuration needed. Note: when embedded cross-site, browsers may
partition or block storage in third-party iframes, which affects persistent
saves (see below). Serving the iframe from the *same* origin as the embedding
site avoids this.

### Option B — direct embed

Add this where the game should appear:

```html
<div style="width:1280px;height:800px">
  <canvas id="canvas" tabindex="-1" oncontextmenu="event.preventDefault()"
          style="max-width:100%;max-height:100%"></canvas>
</div>
<script>var Module = { canvas: document.getElementById("canvas") };</script>
<script src="https://your-host.example/opensupaplex/opensupaplex.js"></script>
```

Caveats:

- `Module` is a plain global and the game auto-starts when the script loads —
  one instance per page, and don't reuse the name `Module` on that page.
- The canvas **must** keep `id="canvas"`; the runtime looks that id up for the
  audio-unlock hook.
- If served from a different origin than the page, the host must send
  `Access-Control-Allow-Origin` for `.js`, `.wasm` and `.data` (and `crossorigin`
  fetches must not be blocked).

## Persistent saves

Savegames, settings and hall of fame are stored in IndexedDB via IDBFS, keyed
to the origin the game runs on (or the embedding site's origin with option B).
Clearing site data deletes them; there is no other copy.

## Updating this folder

After rebuilding (`make -C wasm`), refresh the artifacts with:

```sh
make -C wasm deploy
```

`index.html` and this README live in git; the copied artifacts are gitignored.
